# 新品试用 MVP

连接品牌商家与消费者的新品试用工作流平台。消费者申请通过后免费领取；少数成本较高的样品采用 1–9.9 元象征性体验价。签收后完成真实、结构化反馈，审核通过即完成试用。

第一版重点是把申请、资格、领取、物流与反馈串成一条可追踪、可审计的自动化流程。免费不是无门槛抢购：同一活动一人一份，并结合资格码、历史完成率和异常账号复核控制成本。

## 已实现

### 消费者端

- 浏览试用活动与透明规则
- 提交试用申请，避免同一活动重复申请
- 查看“我的试用”与当前下一步
- 结构化评分、复购意愿、文字与图片反馈演示
- 站内通知与试用状态

### 商家端

- 待办总览与活动漏斗
- 单个申请审核
- 审核通过后自动创建专属资格 Token
- 模拟免费领取/体验价下单、发货与签收
- 签收后自动开启反馈任务
- 反馈审核、退回补充与完成试用

### 平台端

- 重复领取、失效资格与履约异常人工处理
- 一人一份、资格码与历史完成率校验
- 全流程事件审计日志

## 核心设计

- 所有状态变更统一经过 `transitionParticipation()` / `runTransitions()`，UI 不能任意跳状态。
- 每次变更都会生成 `WorkflowEvent`。
- 免费试吃为主，1–9.9 元低价体验为辅；低价只用于减少随手申领，不承担盈利目标。
- 演示数据写入浏览器 `localStorage`，可在商家/平台侧一键重置。
- 静态导出，可直接部署到 GitHub Pages。

## 演示路径

1. 消费者选择“鲜奶小蛋糕新品试吃”，阅读规则并提交申请。
2. 切换为商家，在“申请审核”中通过这份申请。
3. 回到商家总览，依次模拟领取、发货、签收。
4. 切换消费者，在“我的试用”中完成结构化反馈。
5. 商家审核反馈，审核通过后试用直接完成。
6. 在“流程日志”查看每一次状态变化。
7. 切换平台角色，查看资格/履约异常与人工处理流程。

## GitHub Pages

仓库已包含 `.github/workflows/deploy-pages.yml`。推送到 `main` 后，在 GitHub 仓库的 **Settings → Pages → Source** 中选择 **GitHub Actions**，后续提交会自动测试、构建和部署。

GitHub Pages 默认仓库名为 `xinpin-trial-mvp`。如果修改仓库名，请同时修改 `next.config.mjs` 中的 `pagesBasePath`。

## 从演示版走向生产

当前版本是可交互产品原型，不处理真实支付、订单与物流。生产接入前至少还需要：

- Supabase Auth / Postgres / Storage 与行级权限
- 服务端 `TrialWorkflowService` 与数据库事务
- 有赞、微信商城等真实 `CommerceAdapter`
- Webhook 签名验证、定时任务和通知服务
- 领取资格唯一索引、防重复申领、审计权限与人工复核后台
- 手机号脱敏、隐私授权、投诉与安全合规流程
