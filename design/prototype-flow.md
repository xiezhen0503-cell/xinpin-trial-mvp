# 移动端重构原型流程

## 单一任务

让用户在打开页面后的第一个手机屏幕内知道“今天有几款可以申请、哪款免费”，并能顺畅进入详情、申请或订阅开放提醒。

## 视觉计划

- 墨绿 `#123B31`：护照与可信状态。
- 试吃绿 `#18735B`：主操作。
- 珊瑚 `#F47A55`：资格章、免费与截止提醒。
- 芒果黄 `#F3C969`：口感和低价体验。
- 米纸白 `#F6F7F1`、纯白 `#FFFFFF`：食品编辑部底色。
- 展示字：高字重中文黑体，压缩字距；正文：系统中文无衬线；编号：等宽字体。
- 唯一签名：可复用的“试吃护照盖章”，贯穿 Hero、活动资格和申请完成状态。

## 首页结构

```text
顶部栏
今日试吃通行证：3款开放 / 1款免费 / CTA
┌──────────────┐
│ 正在开放：横滑大卡 → │
└──────────────┘
即将开放：两列紧凑卡 + 提醒
大家刚试完：真实评价摘要
四步流程
底部导航
```

## 流程图

```text
发现页 --[查看试用规则]--> 开放活动详情 --[申请试用]--> 申请表单
申请表单 --[有效提交]--> 我的试用
申请表单 --[字段缺失]--> 浏览器内联错误
发现页 --[查看进度]--> 筹备活动详情 --[提醒我开放]--> 已订阅提醒
活动详情 --[返回]--> 发现页顶部对应模块
```

## 验收

- 可申请活动排在筹备活动之前。
- 手机首屏露出开放活动信息或明确可申请数量。
- 进入详情后滚动位置为顶部。
- 详情页手机端始终有固定主按钮。
- 筹备活动可以设置提醒，不出现死按钮。
- 手机端筹备卡两列显示；开放卡横滑并露出下一张。
- ESLint、测试和生产构建通过；浏览器完成申请与提醒两条路径。
